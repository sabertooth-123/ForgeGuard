# AI assistant disclosure

Per the hackathon's rules ("AI coding assistants are allowed, but their use must be disclosed. Do not generate code that we cannot understand, test, or explain"):

**Claude Code (Anthropic) was used throughout this project's development**, from initial architecture design through implementation, debugging, and scenario writing. Specifics:

- **Architecture was designed collaboratively**, not handed a spec and left alone. The original project brief assumed a Python-only stack; Claude Code identified that TrueForge's SDK is TypeScript/Node-only during live research (not from memorized/assumed knowledge), which led to the hybrid TypeScript (DevAgent) + Python (evaluation engine) split actually used.
- **TrueForge API behavior was verified against the live server and its real API responses**, not assumed from documentation alone. Several real discrepancies were found this way and are documented in `docs/trueforge-integration.md` and inline code comments — e.g. the persisted REST events endpoint uses snake_case field names while the live SSE stream (used by TrueForge's own TypeScript SDK) uses camelCase for the same underlying data; request bodies needed different casing than the OpenAPI spec's schema documentation showed.
- **Real bugs were found and fixed by actually running the system**, not just writing code and assuming it worked: a Windows-native startup bug in TrueForge itself (worked around via WSL2), an unhandled exception in TrueForge's sandbox-provider settings UI (root-caused via server logs), an approval-gate evaluator bug that produced a false-positive safety finding (a tool call that errored before reaching the real destructive tool was initially flagged as an "approval bypass" even though nothing dangerous happened), and two scenario-design bugs where a self-seeded malicious file's content ended up embedded in the agent's own tool-call arguments, making those scenarios structurally impossible to pass regardless of agent behavior.
- **Every component was tested before being considered done.** 20 unit tests cover the scenario loader, trajectory normalization, deterministic evaluator, and scorer; the full pipeline (CLI -> Python client -> TrueForge -> local model -> evaluator -> scorer -> reports) was run live against the real server repeatedly, not just unit-tested in isolation.
- **The project's owner (Pranav Gupta) reviewed and directed the work throughout** -- including making the final calls on model provider selection (switching from hosted free-tier APIs to a fully local model after direct experience with real rate-limit and access issues), scope decisions (which scenario categories and tracks to prioritize), and reviewing reported findings (e.g. confirming which evaluator failures were real agent behavior versus false positives worth fixing).

Nothing in this repository is code the project's owner cannot explain -- every non-trivial design decision above was made with, and is documented with, its reasoning.
